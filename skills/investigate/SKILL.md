# investigate

本 skill 是**通用骨架**，不含领域知识。完整方法见 `~/.agents/framework/playbooks/diagnosis.md`。

## 0. 开工前（2 分钟）
1. 入门三问：症状 / 表面 / 已有证据。缺关键 ID → 只问这一个。危险标识（ID 长度不对、陌生表后缀）→ 先停。
2. 写一行：`交付物 = 修故障 | 出分析 | 做设计 | 建需求`。
3. 链接 / 附件 / 截图自己解析下载；时区对齐（每个数据源跑一次 now()）。
4. 扫相关群 / 线程近 24h、已有 PR / 会话：有没有人已否决、已确认、已在做。
5. 有领域 skill 就加载它（路由见 `~/.agents/packs/*/README.md`）。

## 1. 建账本（写在草稿 / 证据文件里，随查随更新）
```
| # | 断言 | 状态 ✓/⚠/✗ | 产物（查询行 / file:line / 日志 / 消息 id） |
```
承重环节有 ⚠ → 不许写「修复是…」。

## 2. 主循环
1. 先排除「还在跑」；再确认「设计如此」（节奏、约定、声明输出）。
2. 画数据 / 控制流，确认线上在用的是哪个副本（`git fetch` 后看 `origin/<main>`、线上配置、部署目标）。
3. 分层状态表，同一快照内对照，找第一个 ❌ 层。
4. 断点：被报告的那个量的 `MAX(date)` → `lag_days`；断点 ±1 周期的变更；「那天还有谁断了」+ 存活分流。
5. ≥3 个可证伪假设，每个配 ≤5 分钟的证伪查询；默认先查配置 / 输入 / 环境 / 部署，再查代码。
6. 对照组或复现：同类兄弟、干净实体、换资源组；能复现就复现。
7. 根因写成：`<具名对象> 在 <条件> 下 <做了/没做 X>，导致 <下游字段> = <值>`。
8. 影响面单独取证：代码可达 / 已观察 / 声称。

## 3. 陷阱自检（发结论前过一遍，命中任一条回到对应步骤）
- 我是不是把设计行为当故障了？（T1）把进行中当失败了？（T2）
- 我选的根因是不是只是最显眼的那个？能解释「刷新一下就好了」吗？（T3/T4）
- 根因的层对吗？配置查过了吗？同一层是不是已经失败两次了？（T5）
- 影响面是数出来的还是推出来的？工单范围是不是只是下限？（T6/T7）
- 这是比较类问题吗（单看任一对象都不异常）？（T8）
- 我引用的数字 / 结论是二手的吗？重算过吗？（T9）
- 时间轴：有断点吗？用的是现值推过去吗？（T10/T11）
- 我是不是在替 PM 定性、替 owner 承诺？（T13）
- 交付物对吗？（T15）派给的人真的会动手吗？（T16）

## 4. 收尾
- 加载 `close-out` 过结案闸。
- 实质性调查 → 文档（每步 Query + 结果 + 解读），链接回写案例库；聊天给「问题 / 原因 / 修复」三句。
- 学到的可泛化判据 → `distill-lessons`。
