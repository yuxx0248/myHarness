# Playbook · 写 skill（Claude Code 与 Codex 通用）

---

## 1. 放在哪

- **跨 runtime 的 skill 放 `~/.agents/skills/<name>/SKILL.md`**，再软链到 `~/.claude/skills/` 和 `~/.codex/skills/`。
  只服务某个 runtime 的（依赖 Claude 的会话管理工具等）才直接放在 runtime 自己的目录。
- 三层分离：**路由层（skill）** + **内容层（知识库）** + **环境层**（个人登录 / 权限，不随 skill 分发）。
- 打包分享时：解引用软链、去个人化（`/Users/<me>/` → `~/`）、扫描结构化密钥。

## 2. SKILL.md 骨架

```markdown
---
name: <kebab-case>
description: <做什么> 当问题涉及以下任一关键词时必须读取本 skill：<关键词堆：表名、服务名、ID、报错原文、口语化症状、人名>。
  不负责：<相邻场景> → 用 <兄弟 skill>。
---

# <名字>

本 skill **不直接执行** / 只做 <X>。（说清楚它是路由、SOP、工作流还是报告）

## 输入（最小集）
| 字段 | 必填 | 默认 | 缺了怎么办 |

## 第 0 步：硬闸（已知会出事的票型，先过 N 步配置检查）
## 第 1 步：FAQ 快查 30 秒（命中 = 起点假设，仍需验证产物）
## 第 2 步：读 SOP 对应章节（grep，不整篇加载）
## 第 3 步：分诊问题
## 第 4 步：核心诊断手法
## 第 5 步：在真实系统里验证
## 决策树
## 输出契约（格式、写到哪、给谁）
## 不要做什么（含已知死路：哪些尝试注定失败）
## 相关 skill
## 案例库（指向 KB 附录；交付物链接回写到这里）
```

## 3. 设计模式

| 模式 | 说明 |
|---|---|
| **skill = 薄索引** | 重内容放 KB，skill 只告诉调用方走哪一步、用什么查询、去哪对账。大文档按章节 grep |
| **description 就是触发面** | 堆满用户可能粘贴的标识符和口语症状；写「当…时必须读取」 |
| **显式的负范围** | 「不要和 X 混淆」「不负责 → 用 Y」，在 description 和正文里都写 |
| **分诊器 vs 领域** | 分诊 skill 只把（来源、告警名、严重度）映射到领域 skill 的章节，过一道误报闸后**立即交棒**，不展开排查、不复制细节 |
| **固定步骤骨架** | 每个领域 skill 同一顺序（见上），读者形成肌肉记忆 |
| **输出契约** | 需要被程序消费时：第一行严格单行 JSON，其余是人读的说明；额外内容不进 JSON，避免破坏解析。skill 只产出，写操作由外层做 |
| **写前先 DIFF** | 任何持久化写入：预览 → 说明写入模式 → 等确认；覆盖只在我明确说「覆盖」时，且先列出会丢的段落 |
| **规则带出处** | 每条规则后面注日期 + case；规则编号跨 SOP / skill 引用，不复制 |
| **注册表驱动扩展** | 「加新服务：复制一个块，按字段填」—— 不改 SKILL.md 和脚本 |
| **skill 内持久缓存** | 能确定性反解的东西（token → id）缓存在 skill 目录，解完追加，带日期备份 |
| **已知死路列表** | 明确列出「禁止做的无意义尝试」，省得 agent 重新发现失败 |
| **上下文预算** | 「不要在主上下文里读 X，交给子 agent」；预处理用脚本；容忍脏的 CLI 输出（找第一个 `{`） |
| **共享前置** | 「开始前必须先读 `../<shared>/SKILL.md`」形成依赖图 |
| **两类读者两份文件** | `SKILL.md` 给 agent；`SHAREABLE.md` 给同事（人读的版本） |
| **最小输入 + 默认值表** | 3 个必填字段，缺哪个问哪个；时间用自然语言解析表 |
| **环境感知的双源** | 本地 grep 失败（沙盒 / TCC）→ 自动改读云端镜像 |
| **横切纪律放 hook，不复制进 N 个 skill** | Claude：PostToolUse(Skill) hook 注入；Codex：写进 AGENTS.md 对应场景段落 |

## 4. 写作规则

- 写成可泛化的判据，**不写个案答案**；示例可以有，但要标明是示例。
- 每条规则一句判据 + 一句原因。
- 中文为主，标识符英文原样。
- 代码里能直接看出来的不抄，只留指针。
- 改了脚本要同步更新 skill 里的命令（过期的 SKILL.md 命令每次运行都会失败）。

## 5. 改 skill 的流程

1. 改之前：确认要改的是规则还是执行（「是规则的错，不是执行的错」）。
2. 出 DIFF → 我确认。
3. 用干净的子 agent 拿原始输入重跑相关历史 case（不给答案），同时在旧版本上跑同一张卷作对照。
4. 通过后合并；如果 KB 有云端镜像，同步。
5. 在反例 / 案例库里记一笔为什么改。
