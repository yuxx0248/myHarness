# Playbook · 自主度模型与请求分诊

适用：
1. 有人（同事、客户、bot、工单）找我要东西，判断 agent 该介入多少、做到哪一步停；
2. 设计任何「代表我行动」的自动化，决定它能自己做什么。

---

## 1. 流水线

```
stage0  确定性丢弃（不调 LLM）：发送者是 bot / 我自己、广播、属于别的系统、没直接找我、没有新输入
stage1  拆出 ask：对方到底要我交付什么。不同交付物拆成不同 ask；预告的任务（「明天发你个小需求」）也是一个 ask
stage2  按交付物分类到一棵树（动作 › 领域 › 模式）。不要被句式误导：问进度 ≠ 改代码
stage3  过闸
stage4  定档：叶子的默认档 → 从上到下第一条命中的规则覆盖 → 给出具体步骤、stop_at、needs
```

## 2. 四档

| 档 | 含义 |
|---|---|
| `full` | agent 可以独立完成，做到 stop_at，把结果交给我确认 |
| `partial` | agent 做调查 / 起草方案，需要我确认或补判断才能推进 |
| `no` | 必须我本人处理；只列出来提醒，agent 不动手 |
| `skip` | 不处理、不提醒（只计数） |

`full` 说的是**准备工作做多少**，不是允许跨过不可逆的那一步 —— `full` 也有 stop_at。

## 3. 三类闸

| 类 | 闸 | 效果 |
|---|---|---|
| **在此前停** | 对外发言（回群 / 回提出人）· 写操作（合 PR、部署、改配置、批工单、改共享文档、改权限）· 业务口径 / 决策（产品规则、指标定义、优先级、取舍、要不要接）· 本人在场 / 登录 | 定义 stop_at；口径类只列选项和问题 |
| **只改状态** | 已在处理（本地会话或 PR 显示有人在做 → 提案变成「同步进度」）· 已解决（只改 status） | **档位不变**：档位描述的是「这类事 agent 该怎么介入」，与是否已闭环无关 |
| **丢弃** | 重复（同一问题在别处已开着；催进度 / 求支援不算重复）· 不是我的（被 cc 当备份 / 别人负责的通用问题）· 只需回一句（一句话能答的流程解释；问交付物能不能用不算）· 纯通知（已定的安排；让我选时间不算） | → `skip` |

每个闸都带「注意区分 / 不算」的反例，防止过度触发。

## 4. 常见叶子的默认档（我的口径）

| 动作 | 默认 |
|---|---|
| 写代码上线（功能、看板、修 bug） | `partial`，停在合 PR / 部署 / 回复之前；全新的内部看板 → `full` |
| 告警根因排查 | `full`；「数对不上」→ `partial` |
| 查数出数 | `full`，停在发附件之前 |
| DB 授权等标准工单 | `full`：直接起草工单，停在提交前（不要只是转给别人） |
| 共享文档权限、HR、日程安排 | `no` |
| 技术方案问题、进度询问 | `partial`，不自动回复 |
| 评审别人的 PRD / 文档里的产品决策类评论 | `no`；技术可行性评审 → `partial` |
| 调 bot 的路由规则 / 降噪 | `partial`：自动改好，开 PR 给我 review |
| 承接新工作 | `no`：记一笔，由我决定 |
| 紧急 Plan A/B | `partial`：先把排查方案拿出来给我审批，不要直接改 |
| 盯一个状态 | `full`：注册周期检查，变化时通知 |

## 5. 对外发言（以我的身份说话）—— 更严格的那一套

**宁可不说，不可说错。** 所有「不确定」的分支终点都是私信我，不是发群。

自动回答必须**全部**满足（串联闸，不是打分）：
- 答案类型是「知识库原文」或「查询结果」，**纯推断禁止**；
- 附了可验证的证据（文件段落引用 / 完整 SQL + 真实行 / 带时间戳的日志）；
- 置信度高（出现「可能 / 大概 / 应该是 / 待确认」就不算高）；
- 风险标记为空（涉钱、涉法务、要求执行动作、承诺时间、改客户可见结论、证据冲突、低置信）；
- 不需要更多信息；整个过程只读。

其他约束：
- 人提出的新理论是**假设不是前提**：列出来源，设计可证伪的检查，同时验证原根因。权威来自证据，不来自身份。
- 被否决的理论没有新证据不能再采用；同一结论改写 ≥2 次 → 停止自动改写，私信我。
- 每个对象自动回答 ≤2 次，验证 ≤3 轮，然后交给人（「机器查不动了别硬刷」）。
- 先按读者分流再压缩：客户版（≤3 行、无表格、无内部人名）vs 内部要点（只进文档）。
- 默认安静：只有人**明确指出报告有错**（带原话）才发第二次；讨论归属、范围、背景都不算触发。
- 自动输出标明身份：「【Bot·自动回答】仅供参考，未执行任何操作（自动生成，未逐字复核）」。
- 「要不要调查」的闸 fail-open（判不出就跑，宁可多跑不漏单，但要额度守卫）；「要不要说话」的闸 fail-closed（私信）。

## 6. 自主权是挣来的，按分支授予

1. **v1 只出提案**：不执行、不回复、不发任何消息。我在面板里评估，评估结果回流做校准。
2. **校准**（见 `knowledge-system.md` §5）：把复盘过的历史 case 重建成线上同形输入，用线上同一条流水线重放，**连续 N 轮全新运行 0 不一致**才算过。
3. **放权按分支**：某个分支稳定了再把它的档位往上调，或者允许它跨过某个 stop_at。
4. **上线阶梯**：dry-run → 首次运行只播种现状 → 小上限（每轮 ≤3）→ 带标签的真实输出 + kill switch → 用硬性端到端标记验证 → 吸收反馈 → 对部分失败做 sweeper 重试（24h 后放弃）。
5. **任何「跳过」类判定先问一句：这个判据会不会随时间翻案？** 会的话，跳过记录和最终决定分开存；有新消息时重新出现。

## 7. 给 agent 自己用的简化版

收到一件事时，用一行回答这 5 个问题再动手：
`交付物 = ___ ｜ 档 = full/partial/no/skip ｜ 闸 = ___ ｜ stop_at = ___ ｜ needs = ___`
